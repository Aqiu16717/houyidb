# HouyiDB 本机性能实测（2026-10）

> [English](houyidb-performance-2026-10.en.md)

> 本文是**单机工程测量记录**，用于比较 HouyiDB 自身不同配置（1×/2×、
> 旧/新合图路径、过滤缓存），**不包含任何第三方产品的对比数据**，也不构成
> 对第三方产品的评价。数字只对文中版本、参数、机器与日期成立。
>
> EN: single-machine engineering measurements of HouyiDB configurations only;
> no third-party comparison data is published here.

## 1. 环境与方法

| 项 | 值 |
|----|----|
| 机器 | Apple Silicon（arm64），8 核，16GB RAM，macOS，AC 电源 |
| 版本 | v0.2.0-beta.5 候选构建（各表来自不同日期，见表中标注） |
| 工具 | VectorDBBench；方法与参数见 `VDBBENCH_PROTOCOL.md` |
| 共同参数 | 非 streaming 场景 k=10，m=24，ef_construction=400，COSINE，load_concurrency=8 |
| 检索并发 | 1 / 8 / 16，每档 30s；ef_search 按场景扫描 |
| 构图 | `PARALLEL_BATCH_BUILD=1`、`MAX_BUILD_BATCH=8192`、`SEED_SERIAL_POINTS=256` |

流程：每个数据集加载一次，随后用 `--skip-load` 跑不同 `ef_search` 的检索；
每次加载前清空数据目录并重启数据库。**不同表格来自不同日期的构建或不同
代码路径，只用于各自场景内的 A/B，不能跨表拼成一个总分。**

HouyiDB 的 level-0 连接密度有两种模式：

- **2×M（当前默认）**：召回优先，兼容已有 2× 图快照；
- **1×M**：高 QPS 档，召回略低（Cohere 场景约 0.9pp）。

两种模式不能在同一份旧图快照上直接切换；切换前确认快照/WAL 完整，或接受
一次全量重放。

## 2. OpenAI 1536D / 50K

| 项 | 2×（2026-10-22） | 1×（2026-10-22） |
|----|-----------------|------------------|
| 加载 | 81.2s（insert 42.6 + optimize 38.6） | **57.2s**（38.9 + 18.3） |
| ef64 recall | 0.9999 | 0.9999 |
| ef64 QPS（c8 / c16） | 426.1 / 400.3 | **686.0 / 680.3** |
| ef128 QPS | 403.9 | **663.5** |
| ef256 QPS | 411.8 | **652.6** |
| ef64 p99 | 9.6ms | **6.0ms** |

同一数据集下，1× 相对 2× 的 QPS 提升约 58–64%，召回不变。

## 3. Cohere 768D / 1M

| 项 | 2×（2026-10-21） | 1×（2026-10-22） |
|----|-----------------|------------------|
| 加载 | 1653.7s（insert 1465.1 + optimize 188.6） | **1012s**（825 + 187） |
| ef128 recall | **0.9971** | 0.9883 |
| ef128 QPS（c8 / c16） | 610 / 614 | **894 / 864** |
| ef256 recall | **0.9971** | 0.9883 |
| ef256 QPS（c8 / c16） | 608 / 627 | **833 / 839** |

1× 的 QPS 更高，代价是召回约低 0.9pp；召回敏感场景用 2×，高 QPS 场景用 1×。

## 4. Label Filter（Cohere 1M，1% labels）

| 项 | 2×（2026-10-22） | 1× + 连续向量缓存（2026-10-23） |
|----|-----------------|--------------------------------|
| 加载 | 1624.1s | **1301.6s** |
| ef128 recall | 1.0000 | 1.0000 |
| ef128 QPS（c8 / c16） | 697 / 698 | **1161.9 / 907.3** |
| ef256 recall | 1.0000 | 1.0000 |
| ef256 QPS（c8 / c16） | 688 / 747 | **1176.4 / 784.2** |

过滤命中量大时，HouyiDB 会按标签惰性构建连续向量缓存（Cosine 预先单位化），
查询退化为顺序 SIMD 扫描 + top-k；写入后按批失效重建，超过 256MB 的标签
回退旧路径。首次实测曾达到 ef128 1361/1365、ef256 1321/1386 QPS；
2026-10-23 复测受后台负载影响为 1161.9/1176.4（conc8），两次都明显高于
同一实现的旧路径。

## 5. Streaming（Cohere 100K，insert_rate=500/s，k=100）

HouyiDB 合图默认「读锁规划 + 短写锁提交」：规划在 HNSW 读锁内并行完成，
提交只持短写锁（实测 3–7ms/批），构图期间检索可并发读图。

| 项 | 旧路径 1×（10-22） | 新路径 1×（10-23） | 新路径 2×（10-23） |
|----|-------------------|-------------------|-------------------|
| 实际写入 | 200.1s | 200.1s | 200.1s |
| optimize | 0.07s | **0.01s** | **0.01s** |
| 检查点 50/80/100/110 | 100.8/206.3/211.2/294.0s | 101.0/**164.4/201.0**/282.5s | 101.0/**165.3/201.0**/284.5s |
| 成熟 recall（100/110） | .988 / .988 | .9876 / .9876 | **.996 / .996** |
| 50% 串行总耗时 / p99 | 104s / 1.72s | **3.9s / 21ms** | 6.3s / 25ms |
| 100% QPS（c5 / c10） | 996 / 1221 | **1103 / 1355** | 740 / 887 |
| 110% QPS（c5 / c10） | 990 / 1175 | **1101 / 1353** | 748 / 894 |

最终 gate 版本复测（2026-10-24）：检查点 100.95 / 164.69 / 200.90 / 283.25s，
recall .5148 / .8307 / .988 / .988，串行 p99 22 / 24.9 / 4.9 / 4.7ms，
100/110% QPS 999/1160、980/1214，与上表在运行方差内一致。

### 早期 recall 的口径

VectorDBBench 的 streaming ground truth 是**全集静态**的，而写入是数据集
行序前缀。CohereSmall 实测 GT@10 可达上限：前 50% 行 0.5030、前 80% 行
0.8031。旧路径的 50% recall .954 是因为查询被构图写锁阻塞（1000 条查询
耗时 104s），多数查询实际在库接近建完后才执行；新路径 3.9s 跑完，量到的
是覆盖率上限（新路径 .515/.826）。

因此**早期 recall 不能跨搜索速度直接比较**；成熟 recall 看 100%/110%。
新路径的代价是批量建库总墙钟约 +11%（Cohere 1M：1170s vs 1055s），对加载
时间极敏感的场景可设 `HOUYI_HNSW_PLAN_APPLY=0` 回退旧路径。

## 6. 结论

1. **1× vs 2×**：1× 在 OpenAI/Cohere 上带来约 35–64% 的 QPS 提升，Cohere
   召回约低 0.9pp；默认保持 2×（快照兼容），高 QPS 场景显式设 1×。
2. **过滤**：连续向量缓存把 ef128/ef256 的 QPS 从约 700 提升到 1100+，
   recall 保持 1.0；写入后缓存失效会带来一次重建成本。
3. **Streaming**：plan/apply 把 50% 阶段 1000 条串行查询从 104s 降到 3.9s、
   p99 从 1.72s 降到 21ms；成熟 recall 不变（1× .9876、2× .996）。
4. 所有结果都是单机、单次运行；比较不同报告时，必须确认机器、模式
   （1×/2×）、`ef_search`、并发与接口路径一致。

## 7. 复现

```bash
# 环境与公平参数见 VDBBENCH_PROTOCOL.md；本仓库不发布第三方系统对比数据，
# 如需外部对照，请按协议自行执行并注明版本、参数与机器。
export VDB_ROOT=/path/to/VectorDBBench   # 含 houyidb client 适配器
./scripts/vdbbench_qdrant_houyidb_gate.sh check
./scripts/vdbbench_qdrant_houyidb_gate.sh run-houyidb

# 1× 模式（高 QPS）
HOUYI_HNSW_LAYER0_MULT=1 ./scripts/vdbbench_qdrant_houyidb_gate.sh run-houyidb

# 回退旧合图路径（对照）
HOUYI_HNSW_PLAN_APPLY=0 ./scripts/vdbbench_qdrant_houyidb_gate.sh run-houyidb
```
