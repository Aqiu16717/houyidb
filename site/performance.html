两种 level-0 连接密度。 2×M 是当前默认：召回优先，兼容已有 2× 图快照。1×M 是高频 QPS 档：召回略低（Cohere 场景约 0.9pp）。两种模式不能在同一份旧图快照上直接切换；切换前确认快照 / WAL 完整，或接受一次全量重放。

构图使用 PARALLEL_BATCH_BUILD=1、MAX_BUILD_BATCH=8192、SEED_SERIAL_POINTS=256。完整参数、公平性原则与结果记录模板见 VDBBENCH_PROTOCOL.md ↗。

1× vs 2×：速度与召回的交换。

默认 2× 优先召回与旧快照兼容；1× 把 level-0 连接数减半，换取更高 QPS。以下两组数据只做同场景内的 A/B。

结论只在同一数据集内成立。 OpenAI 50K 上，1× 的 QPS 提升约 58–64%，召回不变；Cohere 1M 上，1× 的 QPS 更高，但召回低约 0.9pp。默认仍保持 2×；召回敏感场景用 2×，高 QPS 场景显式设 1×。

过滤缓存：把随机访问变成顺序 SIMD。

在 Cohere 1M、1% labels 的过滤场景里，命中量大时 HouyiDB 会按标签惰性构建连续向量缓存（Cosine 预先单位化），查询退化为顺序 SIMD 扫描 + top-k。两种路径的 recall 均保持 1.0000。

Streaming：把 104 秒压到 3.9 秒。

合图默认「读锁规划 + 短写锁提交」：规划在 HNSW 读锁内并行完成，提交只持短写锁（实测 3–7ms/批），构图期间检索可并发读图。场景为 Cohere 100K、insert_rate=500/s、k=100。

早期 recall 不能跨搜索速度直接比较。 VectorDBBench 的 streaming ground truth 是全集静态的，而写入是数据集行序前缀。CohereSmall 实测 GT@10 可达上限：前 50% 行 0.5030、前 80% 行 0.8031。旧路径 50% recall .954 是因为查询被构图写锁阻塞（1000 条查询耗时 104s），多数查询实际在库接近建完后才执行；新路径 3.9s 跑完，量到的是覆盖率上限（.515 / .826）。成熟 recall 看 100% / 110%。

新路径的代价是批量建库总墙钟约 +11%（Cohere 1M：1170s vs 1055s）；对加载时间极敏感的场景可设 HOUYI_HNSW_PLAN_APPLY=0 回退旧路径。最终 gate 版本 2026-10-24 复测：检查点 100.95 / 164.69 / 200.90 / 283.25s，recall .5148 / .8307 / .988 / .988，串行 p99 22 / 24.9 / 4.9 / 4.7ms，100/110% QPS 999/1160、980/1214，与上表在运行方差内一致。

复现，以及不要做的事。

完整 case、参数与结果记录模板见 VDBBENCH_PROTOCOL.md ↗。下面是 HouyiDB 侧自测门禁的最短路径。

Terminal / reproduce bash 
export VDB_ROOT=/path/to/VectorDBBench   # 含 HouyiDB 适配器的工作副本
./scripts/perf_regression_gate.sh vdb

# 高 QPS：1×M
HOUYI_HNSW_LAYER0_MULT=1 ./scripts/perf_regression_gate.sh vdb

# 对照：回退旧合图路径
HOUYI_HNSW_PLAN_APPLY=0 ./scripts/perf_regression_gate.sh vdb
注意：自测门禁会执行 preflight，停止本机旧的 houyi-server、释放开发端口并清理开发 WAL。生产环境不要执行。 完整对照流程与 clean-room 约定以协议文档为准。
  • 不拼总分不同表格来自不同日期或代码路径；每张表只做自身的 A/B。
  • 不混口径跨机器、模式（1×/2×）、ef_search、并发或接口路径的数字不能直接比较。
  • 不切旧图不要在旧图快照上直接切换 1×/2×；先确认快照 / WAL 完整或接受全量重放。
  • 不是基准以上是单机、单次运行的本机工程测量，不代表任何实验室或外部环境的结果。
