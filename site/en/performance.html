Read the method before the numbers.

All figures come from the same class of machine and process: each dataset is loaded once, then ef_search is swept with --skip-load; the data directory is cleared and the server restarted before every load. Different tables come from different dates or code paths, so they are A/B comparisons within one scenario, never a combined score.

Bars are normalized to the maximum value within their own figure and serve only relative comparison inside that figure; exact values are printed at the end of each bar or in the data table.

Two level-0 connectivity modes. 2×M is the current default: recall-first, compatible with existing 2× graph snapshots. 1×M is the high-QPS mode: slightly lower recall (about 0.9pp on Cohere). Do not switch modes on an existing graph snapshot; confirm snapshot / WAL integrity first or accept a full replay.

Build tuning uses PARALLEL_BATCH_BUILD=1, MAX_BUILD_BATCH=8192, and SEED_SERIAL_POINTS=256. Full parameters, fairness rules, and the result-record template are in VDBBENCH_PROTOCOL.en.md ↗.

1× vs 2×: speed traded for recall.

The default 2× prioritizes recall and compatibility with existing snapshots; 1× halves level-0 connectivity for higher QPS. Both datasets below are A/B comparisons inside their own scenario.

These conclusions hold only within each dataset. On OpenAI 50K, 1× raises QPS by roughly 58–64% with unchanged recall. On Cohere 1M, 1× has higher QPS but about 0.9pp lower recall. The default remains 2×; use 2× when recall matters and set 1× explicitly for high-QPS workloads.

Filter cache: random access becomes sequential SIMD.

In the Cohere 1M, 1%-labels filter scenario, HouyiDB lazily builds a contiguous vector cache per label when a filter hits many rows (Cosine vectors are pre-normalized), so the query degrades to a sequential SIMD scan plus top-k. Recall stays at 1.0000 on both paths.

Streaming: 104 seconds down to 3.9.

Graph merge defaults to "plan under a read lock, commit under a short write lock": planning runs concurrently inside the HNSW read lock, while commit holds the write lock for only 3–7ms per batch (measured), so searches can read the graph during construction. Scenario: Cohere 100K, insert_rate=500/s, k=100.

Early recall cannot be compared across search speeds. VectorDBBench's streaming ground truth is fully static, while writes arrive as a prefix of the dataset rows. The measured GT@10 ceiling for CohereSmall is 0.5030 for the first 50% of rows and 0.8031 for the first 80%. The old path's 50% recall of .954 came from queries blocked by the graph-build write lock (1,000 queries took 104s), so most queries actually ran after the index was nearly complete. The new path finishes in 3.9s and therefore measures the coverage ceiling (.515 / .826). Judge mature recall at 100% / 110%.

The new path costs about 11% more wall-clock time for a full bulk build (Cohere 1M: 1170s vs 1055s); if load time is critical, set HOUYI_HNSW_PLAN_APPLY=0 to fall back. The final gate build was rerun on 2026-10-24: checkpoints 100.95 / 164.69 / 200.90 / 283.25s, recall .5148 / .8307 / .988 / .988, serial p99 22 / 24.9 / 4.9 / 4.7ms, and 100/110% QPS 999/1160 and 980/1214, consistent with the table within run variance.

Reproduce, and what not to do.

Full cases, parameters, and the result-record template are in VDBBENCH_PROTOCOL.en.md ↗. The shortest path to the HouyiDB-side self-test gate is below.

Terminal / reproduce bash 
export VDB_ROOT=/path/to/VectorDBBench
python3 benchmarks/vectordb_bench_houyidb/install.py --vdb-root "$VDB_ROOT"

# Start houyi-server, then run
VDB_ROOT="$VDB_ROOT" ./benchmarks/vectordb_bench_houyidb/run_bench.sh

# 1× / old graph-merge path: set before starting the server
# HOUYI_HNSW_LAYER0_MULT=1 / HOUYI_HNSW_PLAN_APPLY=0
Warning: the benchmark writes/rebuilds a test collection. Use an isolated empty WAL and data directory; do not point it at production data. The protocol defines the full flow.
